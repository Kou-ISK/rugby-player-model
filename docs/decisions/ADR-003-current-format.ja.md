# ADR-003: 0.4.0内の現在形式を一本化する

[English](ADR-003-current-format.md) | [日本語](ADR-003-current-format.ja.md)

状態: セッション担当者の指示による実装方針。認知仮説の採用ではない。

記録の種類ごとに現在の表現を一つだけ使う。場面3、観測3、知覚2、trace 4、実行envelope 2、snapshot・履歴2、session envelope 2とし、アプリのバージョンは0.4.0に保つ。番号は異なる種類の記録の識別であり、利用者が選ぶ製品世代ではない。同じリリースの開発途中の変更で世代を増やさない。

知覚する情報、運動のシミュレーション、受け手比較の仮説の違いは、同じ形式の設定または取得済み情報で表す。観測形式の版で認知処理を選ばない。新しく生成するtraceの形式とmodel revisionは共通にし、局面・比較・運動の詳細の有無は実際の入力と能力による。

過去の記録は不変の証拠として残す。読込・importの境界でコピーを現在形式へ変換する。観測の追加、時刻の変更、モデルの採用、記録済み結果の再計算結果による置換はしない。原本のbytesとhashを保存し、過去の結果を現在のengineによる結果と呼ばない。変換できない・意味が曖昧な入力では情報を創作せずエラーにする。

通常のwriter・例・schemaは現在形式だけを使う。旧版の処理はimport adapterに集め、認知・描画・exportを新旧で二重実装しない。研究用の比較対象は設定として残し、基準の受け手選択policyを別のlegacy製品として扱わない。

現在形式の出力、取得情報の保存、過去データのimport、形式変更だけの場合の挙動、未知の版・fieldの拒否、ブラウザのcapture・restoreを検証する。私的sessionの原本と無関係な作業中の変更を保護する。

motor場面はoriented知覚と身体相対の球配置を必要とします。実行できない組合せは事前に拒否し、形式番号による暗黙の能力切替は行いません。
