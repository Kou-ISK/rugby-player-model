# ADR-002：モデル、研究、公開の境界

[English](ADR-002-research-boundaries.md) | [日本語](ADR-002-research-boundaries.ja.md)

状態：実装境界として採用。認知仮説や私的候補の採用ではありません。

## 決定

実験ごとにファイルを動かさず既存分離を維持します。再利用する成果物は観測だけの実行モデル、独立した判断文書、ローカル研究道具です。実験は機構・証拠を変え、ディレクトリ責務を変えません。

| ディレクトリ | 責務 | 持たせないもの |
|---|---|---|
| `models/player/` | 観測契約、認知、mode、単独API、試験/card | 世界真値、描画、session filesystem、AI通信 |
| `models/judgment/` | 自己完結文書、選手guide、凍結原本 | runnerや特定AI vendorへの依存 |
| `tools/simulation/` | 合成世界、知覚、対応身体実行 | 認知policy、採否、browser UI |
| `tools/experiments/` | 不変入力、候補、比較、packet、来歴 | UI操作、内蔵AIサービス |
| `tools/workbench/` | 表示、CLI/HTTP、保存、描画adapter | 認知の二重実装、原則の自動コンパイラ |
| `evaluation/` | 許諾済み合成刺激、採点基準、旧baseline | 私的指導、実試合・選手データ |
| `docs/` | 設計判断、手順、範囲、検証 | 本人専用計画、私的導入ログ、会話 |
| `scripts/` | build、再現、境界検査 | 研究ルール、隠れたruntime処理 |

rootのsrc/serverは互換入口です。新実装は上記へ置き、別の互換変更を記録するまで旧importを保持します。攻守で知覚・記憶・判断状態を複製せず、共通観測の上に局面別目標・技能を置きます。保持・役割・不明は実装前に契約を定め、非保持を守備と決めません。

依存はworkbench→experiments/simulation/player、experiments→simulation/player、simulation→player契約です。選手モデルは単独実行、判断文書は単独読取を維持します。純粋な表示契約を共有し、browserからserverをimportしません。固定vendor・判断原本は改変せず周囲で適応します。

## 設計判断が必要な変更

新しい観測・状態、保持切替、身体技能、多人数更新順、保存・通信形式には、理由、情報境界、代替、互換計画を先に記録します。新場面は通常moduleではなくfixtureです。認知には因果比較、技能追加には認知改善と分けた評価が必要で、parameterとcode変更を区別します。

## 公開履歴

公開commitは過去の成果物を識別します。成熟して見せる目的だけで書き換えません。整理には原本、固定hash、engine版対応を維持します。秘密漏洩は個別に対応し、履歴書換だけで認証情報の失効や他のコピー削除にはなりません。

未公開作業は境界を先に決め、設計契約・実装・必要な根拠をまとまったreview可能なcommitにします。未公開fixupはreview前に整理可能ですが、無関係なUI・モデル・採否を混ぜません。repo手順と明示許諾した履歴操作に従い、公開branchへのforce-pushを通常清掃にしません。

公開前にstaged差分、新規一覧、来歴・許諾を確認し、必要検証を実施します。私的workを丸ごとstageせず、ソフトウェア結果、人間受入、科学的妥当性を区別します。manifestはコード一覧で私的データではありません。本書の編集はcommit/push・履歴書換の許可ではありません。

## 結果

互換処理と歴史資料は一部残ります。見た目だけの整理で再現参照を壊さず、上位構成を維持して仮説・守備技能・評価手順を発展させられます。貢献者は責務ごとの正本が分かり、AI API口座なしで道具を動かせます。
