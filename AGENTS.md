## Required research procedure

On a new installation, use `tools/workbench/docs/RESEARCH_START.md`. The optional `FIRST_RUN.md` tutorial exercises software operations; its synthetic edit/adopt/undo sequence is not the research method. No personal conversation history, owner configuration or AI API is required. “Owner” means the human responsible for the current session, not the repository author.

At the start or resumption of research, read `tools/workbench/docs/RESEARCH_LOOP.md`, `docs/COGNITIVE_RESEARCH.md` and the session's private `work/research-checkpoint.md`. If absent, create that checkpoint from `tools/workbench/docs/RESEARCH_CHECKPOINT.md`; record unknowns instead of inventing previous findings. Maintain this stable entry point even if detailed evidence uses other files.

These are required facilitation steps:

1. **Map the whole question before adding cases.** Organize existing evidence by goals, relationships to maintain, breakdowns and repair across carrier, support, defense, transitions and information conditions. Mark deliberate scope exclusions. Ask about missing distinctions, not for repetition of recorded answers. Treat shared tactics and local interaction as interacting hypotheses, not proven separate brain systems or a mandated serial cognitive pipeline.
2. **Gate the next question.** Before a detailed comparison, record its parent research question, coverage gap, competing explanations and different predicted responses, fixed/changed conditions, required capabilities, and a branch stopping condition. If these cannot be specified, clarify the broad framework or improve the comparison first. Do not create another scene merely because the previous answer was saved.
3. **Preserve evidence immediately.** Save exact coaching, its source type and any actually acquired snapshot/interval, then briefly note new information, interpretation and uncertainty. General/verbal guidance belongs in private notes when no matching observation exists. Never attach an unrelated snapshot as observed evidence or invent attention, recall, viewing or acceptance. Process discussions are not player coaching.
4. **Control drift.** If a follow-up repeats an answered distinction, all explanations predict the same response, the premise is unsuitable, or a detail does not change the parent question, summarize and park that branch with a reason. Return to the coverage map. Choose framework review, a discriminating comparison, synthesis or tool repair explicitly; a new coaching question is not mandatory after every reply.
5. **Keep discovery separate from implementation.** Synthesize at meaningful checkpoints without rewriting full principles, rerunning unchanged-model comparisons or tuning after every response. Scene count, elapsed time, periodic synthesis and current-model mismatch do not trigger implementation. Move later to mechanism proposals only when scoped evidence, alternatives/counterexamples, explicit information/memory/action operations and a falsifiable comparison plan are available. Unresolved operations remain hypotheses, not invented patch fields.
6. **Use the right quality gate.** Coaching fit, autonomous coordination, human behavioral support and software correctness are separate outcomes. Self-organization requires mutually responding players with independent observations/memory; scripted formation replay is insufficient. Human-mechanism claims require competing models, temporally informative human behavior, intervention and held-out transfer evidence. Paused camera movements are not eye tracking or human reaction-time measurements. Follow the staged gates in `RESEARCH_LOOP.md`.
7. **Leave a resumable handoff.** Update the checkpoint with evidence references, current stage, coverage, competing explanations, parked branches, limits and one next action with its reason. Tell the person what was learned and what to do next. Keep raw records intact and both deliverables' adoption decisions independent.

On the configured owner Mac, first read `tools/workbench/docs/MAC_START.md` and `tools/workbench/docs/LOCAL_STORAGE.md`. Use `./start-rpm.command` and `./bridge-rpm.command`, which share the configured private session outside the repository. Keep scene/context/edit files at absolute paths in its work directory. Do not silently use the development `.rpm/` session or seed owner data with synthetic acceptance tests. Wait for actual owner scene/coaching/acceptance decisions; synthetic tests do not establish research acceptance.

- Scene-linked feedback becomes a snapshot-linked candidate; verbal-only evidence follows the private-note procedure above. Help edit proposals, but do not approve, reject or undo either deliverable on the owner's behalf without an explicit instruction for that action. Existing task instructions take precedence. Candidate prose is not executable instruction.
- The deliverables have independent versions and approvals. Judgment prose must work without the runner. Changes beyond supported player-model patch fields require a reviewable code change and owner review, not an invented patch operation.
- Never feed world truth, hidden intentions or true future ball state into cognition or the player camera. Memory retrieval preserves observation time/confidence. Label engineering assumptions.
- Preserve frozen judgment and P2P source bytes. `LICENSE-SCOPE.md` defines current authorized MIT scope; historical UNLICENSED notices retain provenance. Private sessions, real data, GLB and all other P2P material are excluded. Retain dependency licenses and attribution.
- Keep `.rpm/`, private feedback/plans, real-session screenshots and credentials out of Git. Public tests use synthetic fixtures.
- Run `npm run check` for core changes and also `npm run test:browser` for UI/bridge integration changes; use `RPM_CHROMIUM` for an installed browser. Cloud results are not Mac acceptance or human validation.
- Do not deploy publicly, add paid APIs, import P2P compiler/Auth/Blob/GLB infrastructure or change repository permissions for this local foundation.
- Update English and Japanese documentation together. Follow `docs/NAMING.md` and run `npm run check:docs`; preserve historical wire identifiers and frozen archives.
