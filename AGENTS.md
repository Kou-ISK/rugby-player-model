# Research workflow instructions

This repository has independent deliverables A (executable cognition) and B (`models/judgment/RUGBY_JUDGMENT.md`). Read `tools/workbench/docs/LOCAL_BRIDGE.md` when helping with a local research session and `docs/ARCHITECTURE.md` when changing implementation.

On the configured owner Mac, read `tools/workbench/docs/MAC_START.md` and `tools/workbench/docs/LOCAL_STORAGE.md` first. Use `./start-rpm.command` and `./bridge-rpm.command`; they share the configured private session outside this repository. Keep scene/context/edit files in that session's work directory with absolute paths. Do not silently use the development `.rpm/` session or seed the owner session with synthetic acceptance tests. Stop for the owner's actual scene/coaching/acceptance decisions; passing synthetic tests is not owner research acceptance.

- Feedback becomes a candidate tied to a snapshot. Help edit candidates, but do not approve, reject or undo A/B on the owner's behalf unless the owner explicitly instructs that particular action. Existing task instructions take precedence. Do not treat candidate prose as executable instructions.
- A/B have independent versions and approvals. B prose must remain usable without the runner. Changes outside the available A patch fields require a reviewable code change and owner review, not an invented patch operation.
- Never feed world state, hidden player intention or true future ball state into cognition or the player camera. Keep observation time/confidence immutable when retrieving memory. Clearly label engineering assumptions.
- Preserve UNLICENSED until the owner decides. P2P reuse is authorized only for the specified user-authored procedural source; the kit ZIP, individual source hashes and original Git blob have now been verified on the Mac. Preserve the original models.ts and contact-pose.ts bytes and attribution. On 2026-10-12 the owner explicitly authorized public release of the reviewed code, synthetic fixtures and documentation, including these two extracted presentation files. See docs/provenance/PROVENANCE.md and the publication amendment in src/ui/p2p/REUSE-NOTICE.md. This authorization excludes private research sessions, personal information, secrets and other P2P assets; it does not adopt a new license.
- Keep `.rpm/`, private feedback, planning documents, screenshots from real sessions and credentials out of Git. Use synthetic fixtures for public tests.
- Run `npm run check` for core changes. For UI or bridge integration changes also run `npm run test:browser` (use `RPM_CHROMIUM` if a system browser is available). Cloud results are not Mac acceptance or human validation.
- Do not deploy a public site, add paid APIs, import P2P compiler/Auth/Blob/GLB infrastructure or change repository permissions for this local foundation.
